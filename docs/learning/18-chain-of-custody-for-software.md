# Chain of Custody for Software

## Established technical concept
Software custody links observed inputs, controlled transformation, output identity and signer.
## Plain-language explanation
Each handoff needs evidence showing what entered, what happened and what emerged.
## Why AI coding agents struggle
Agents jump from source familiarity to deployment confidence without proving transitions.
## Itzako example
Phase 2B links dirty source bytes to copied snapshot, controlled build, payload and signature.
## Kratos Agent Guard implementation
Mutation witnesses, manifests, command evidence and attestation verification prove each handoff.
## Trade-offs
Runtime and loaded-client custody still require target-side identity instrumentation.
## Failure modes
Unwitnessed copying, mutable tags, missing trust roots or promotion without runtime proof.
## Practical exercise
Tamper with the candidate payload and rerun verification.
## Transfer
Use the custody chain for all KratosLab deployment artefacts.
## Key takeaway
Trust the chain only as far as its last independently proven handoff.
