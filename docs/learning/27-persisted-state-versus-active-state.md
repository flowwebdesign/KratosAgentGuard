# 27. Persisted state versus active state

## Established technical concept
Durable registration, process liveness, and active execution are separate states.
## Plain-language explanation
A saved worker registration does not mean the worker is awake.
## Why AI coding agents struggle
Static files are easier to inspect than ephemeral runtime targets.
## Itzako example
An MV3 service-worker path in manifest.json proves configuration only.
## Guard implementation
The current-worker gate remains UNPROVEN without passive authorised target evidence.
## Trade-offs
Accurate runtime claims may require a later controlled observation phase.
## Failure modes
Inferring activity from timestamps, registration files, or browser existence.
## Practical exercise
Order manifest, registration, worker URL, and runtime attestation by strength.
## Transfer
Apply this to queued jobs versus executing workers.
## Key takeaway
Persistence records intent; active-state evidence records execution.
