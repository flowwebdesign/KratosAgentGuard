# Proof scope and non-transferability

## Established technical concept
Evidence does not transfer between different subjects, environments, or claims without a proven link.

## Plain-language explanation
Proving one box does not colour every neighbouring box green.

## Why AI coding agents struggle
Agents optimise for a single success label and flatten qualified states.

## Concrete Itzako example
An isolated loaded extension can be proven while promotion, normal-profile loading, and product behaviour remain unproven.

## Kratos Agent Guard implementation
Six runtime scopes carry independent `EvidenceState` values and qualified gates.

## Trade-offs
Reports are more verbose but prevent dangerous release claims.

## Failure modes
Using canary proof for `current-loaded-client` or behaviour proof is an invalid scope transfer.

## Practical exercise
Build a proof matrix with one row per scope and name the missing link.

## Transfer to another KratosLab project
Separate local, CI, staging, hosted, and production evidence.

## Key takeaway
Every proof answers one scoped question; links must be demonstrated, never assumed.
