# Lesson 48: Fixture proof versus production proof

## Established concept

Evidence from one environment does not transfer automatically to another.
## Plain-language explanation

Passing controlled journeys is not the same as passing with real accounts, data, and services.
## Why AI agents struggle

Agents tend to summarise several green layers as “ready”.
## Itzako example

Phase 2G proves sealed isolated runtime and offline journeys; real backend and normal Chrome remain unproven.
## Guard implementation

Reports expose separate fixture, backend, normal-profile, and promotion verdicts.
## Trade-offs

More verdicts are verbose but prevent unsafe release conclusions.
## Failure modes

Calling fixtures production journeys or granting promotion from isolated runtime.
## Practical exercise

Write independent verdicts for source, build, fixture, hosted, and user-profile proof.
## Transfer

Use scoped verdicts in CI, staging, and regulated systems.
## Key takeaway

Proof is only valid inside its observed boundary.
