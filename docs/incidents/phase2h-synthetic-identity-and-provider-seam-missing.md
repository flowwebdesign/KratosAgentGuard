# Incident: Phase 2H synthetic identity and provider seam missing

## Observation

Phase 2H could inspect the canonical backend and design capped real-backend journeys, but it found no authorised synthetic identity, scoped token, deterministic provider scenario seam, or independent writer authority suitable for dispatch.

## Impact

The sealed extension and offline fixture journeys remained valid evidence, but real backend, queue, PostgreSQL persistence, wrong-language repair, and independent database readback could not be certified. Canonical writer authority was present and intentionally untouched.

## Root boundary

The missing capability was environmental authority, not a candidate failure. Adding test hooks to canonical Study Pilot would have exceeded mutation authority and risked normal runtime semantics.

## Resolution

Phase 2I established a separate backend Git authority, dedicated PostgreSQL database and roles, synthetic identity/token, run-scoped scenarios, exclusive audit lease, signed reproducible build, isolated runtime, Guard-only network translation, and read-only persistence verification.

## Prevention

Future real-backend plans must prove the exact identity, database, provider, lease, cost, and runtime boundaries before dispatch. When any is absent, fail closed instead of borrowing canonical authority.

## Remaining limitation

The resolution proves the isolated audit environment only. Canonical runtime, real provider, normal Chrome, and promotion remain unproven and unauthorised.
